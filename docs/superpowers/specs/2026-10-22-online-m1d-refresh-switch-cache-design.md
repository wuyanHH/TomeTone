# TomeTone 在线听书源 M1-D 详细设计文档：刷新、换源、预下载缓存与删除护栏

- **日期**：2026-10-22
- **状态**：Approved & Plan Ready（已通过两轮实施工程师技术审查并完成决策收敛）
- **适用版本**：M1-D 里程碑
- **关联设计**：`docs/superpowers/specs/2026-10-20-online-book-sources-design.md`

---

## 1. 意图与核心目标 (Intent & The Why)

在 M1-A（书源导入与存储）、M1-B（发现搜索与详情预览）以及 M1-C（在线书入库、书架混排与流式播放）落地后，TomeTone 已经具备了完整的在线听书闭环。但在真实复杂网络环境与长期使用中，用户面临以下关键痛点：
1. **音频失效或源端断更**：书源可能因反爬、下架或地址变更导致音频 403/404，或者章节不全；用户需要能平滑换源，而不丢失历史收听进度、分类标签与手动修改的信息；
2. **切章卡顿与网络延迟**：流式播放每次切章都需要现场向书源发起一次 HTTP 音频解析与连接，体验不够丝滑；需要静默预下载让切章零缓冲；
3. **书目状态演进与保护**：连载书更新后需刷新目录；若网络抖动，绝不能因刷新中途失败而清空已有目录或丢弃已收听章节；
4. **资产安全与误删风险**：书库删除必须严格区隔「在线书移出书架」「在线书彻底删除」「本机书移除书库索引」与「物理删除本地音频文件」。

### 核心用户诉求：**极致流畅，并且页面好看**。

## 2. 目标、非目标与反目标 (Goals, Non-Goals & Anti-Goals)

### 2.1 目标 (Goals)
1. **换源平滑（Switch Source）**：
   - 详情页与播放器提供 Material 3 沉浸式底部抽屉（BottomSheet）；
   - 自动在所有已启用书源中按书名并发检索，展示各源的响应状态、总章节数及与当前收听章节的智能匹配度（如「✓ 完美匹配第 42 章」）；
   - 确认换源后保留 `books.id`、书架分类与标签、手动元数据；将旧章标记为 `retired`，写入新源章节；
   - 进度智能对齐，若映射失败保留原章进度并明确提示，绝不静默覆盖；同时清理该书旧源音频缓存；
   - 若目标源在书库中已存在同名书，阻止合并并提示用户。
2. **多层级无感刷新（Refresh Flow）**：
   - 单本信息刷新：仅更新书源提供的最新描述、封面等，不覆盖用户本地手动修改的覆盖字段（`book_metadata_overrides`）；
   - 单本目录刷新：支持跟随 `nextTocUrl` 完整抓取多页目录（最多 50 页防死循环）；**只有在目录全部抓取成功时**，才允许对消失的章做 `missing`/`retired` 处理；分页中途中断按「部分刷新」保护，保留原目录，状态标记「目录部分刷新」，绝不丢章；
   - 书库批量刷新：顶部提供全局刷新入口，异步非阻塞后台执行，界面顶部通过轻量呼吸微胶囊展示进度，支持随时收起，不锁死 UI。
3. **智能预下载与 LRU 缓存池（Pre-download & LRU Cache）**：
   - 预载窗口：默认在当前章节播放过半（≥ 50%）时，后台静默将后续 3 章（设置 0~10 章可调）音频下载至沙盒缓存，切章即刻秒播；
   - 流量护栏：默认开启「仅在 Wi-Fi 下预下载」，蜂窝网络下仅单章流式；
   - 缓存上限与 LRU：默认上限 2.0GB，超出后按最近最少使用淘汰未在播放队列的过期音频；
   - 视觉美感：播放器进度条采用流式双层轨道高亮，章节列表展示细致的缓存微标识。
4. **分级删除护栏（Delete Guardrails）**：
   - 在线书：区分「移出书架」（保留在书库与收听历史）与「从书库删除」（清除书籍、章节及临时缓存）；
   - 本机书：点删除时弹窗明确区分「从书库移除记录」与可选复选框「同时物理删除音频文件夹」；若勾选物理删除，需二次显式确认。

### 2.2 非目标 (Non-Goals)
- 本阶段不做完整离线整本下载器或多线程并行批量下载管理器（仍属于预下载 LRU 范畴）；
- 不做 HLS（`.m3u8`）分片文件的落盘预下载（HLS 继续保持直接流式播放）；
- 不做付费绕过、验证码自动识别、防盗链破解。

### 2.3 反目标 (Anti-Goals)
- 严禁因单本刷新失败导致整个书库批量刷新中断或界面大面积白屏/报错；
- 严禁单本刷新失败污染书源级的健康度（书源健康仅由源管理/测试/搜索维护）；
- 严禁在换源或刷新中途静默丢失用户的播放进度、书签、分类或修改过的元数据；
- 严禁在删除操作中默认勾选或静默执行对用户本地物理音频文件的删除。

## 3. 架构落地与技术决策规范 (Builder Technical Decisions)

### 3.1 换源卡片试听设计（Decision: 抽屉内独立 PreviewAudioPlayer）
- **背景与约束**：换源确认前，候选源的章节尚未入库。若借用全局 `PlaybackController`，会导致无 `chapter_id` 的外键崩溃或污染用户当前进度。
- **技术决策**：
  - 换源抽屉内使用轻量级专用的 `PreviewAudioPlayer`；
  - 用户点「试听当前章」时，主播放器平滑暂停（不销毁其播放队列和进度）；
  - `PreviewAudioPlayer` 直连临时解析出的候选音频 URL 试听片头；
  - 抽屉关闭、切卡片或确认换源时，自动 dispose 试听播放器，安全无残留。

### 3.2 章节对齐探针与深度进度处理（Decision: 选卡按需探测 + 有界抓取）
- **背景与约束**：Legado TOC 是 forward-only 链表分页，无法直接随机访问后半段章节；全量盲目并发抓取会触发源端反爬限制。
- **技术决策**：
  - 搜索结果卡片初始展示搜索基础信息（最新章、耗时、源名称）；
  - 当用户在抽屉中点选某候选源时，才触发该候选源的目录探针；
  - 若用户当前进度在第 1~50 章，仅抓取第 1 页进行秒级匹配；
  - 若用户当前进度在深度章节（如第 350 章），探针按 50 章/页向前步进抓取（最多抓取 5 页）；
  - 若命中则打上对齐标记；若超过 5 页步长仍未到达，明确展示「当前进度较深（第350章），换源后可手动切章，原进度保留」。

### 3.3 数据库防冲突与多次换源处理（Decision: Upsert 激活 + 保留源归属）
- **背景与约束**：SQLite 存在 `chapters_binding_unique (library_root_id, file_path)` 唯一约束。用户在源 A -> 源 B -> 源 A 来回切换时，若直接更新或插入会触发唯一键冲突。
- **技术决策**：
  - 换源写入时对章节使用 `insertOnConflictUpdate`：若 `(library_root_id, file_path)` 已存在，将其 `retired` 重新置为 `false`，并同步更新标题与序号，无需重复插入；
  - 旧章保留在原虚拟 `library_root_id` 下，打上 `retired = true`；书源停用或删除时仅软停用，绝不连带清空已入库书籍的退役章。

### 3.4 未映射成功时的进度防覆盖保护（Decision: 锁定原进度 + 手动解锁）
- **背景与约束**：换源若未精确匹配，新播放器默认定位到新源第 1 章；如果直接起播，10 秒后的定时器会覆盖 `playback_progress` 抹杀历史进度。
- **技术决策**：
  - 换源映射失败时，数据库 `playback_progress` 继续保持原样（指向旧退役章和旧时间点）；
  - 新播放器保持暂停就绪状态，界面弹黄色保护横幅：「换源未对齐章节，原进度保留在 [第42章]，点击【从新源第1章开始】或手动选章」；
  - 只有用户显式点击开始播放或点击新目录章节后，才解除保护并写入新进度。

### 3.5 预下载作用域与网络状态感知（Decision: 纯未来预载 + connectivity_plus 契约）
- **预下载范围**：
  - 播放器切章或首次起播时，当前章走直接网络流式；
  - 预下载器严格只针对未来章节（N+1..N+3）进行静默下载，绝不同步下载当前正在播放的章节，杜绝流量翻倍与带宽竞争；
- **网络状态感知**：
  - `pubspec.yaml` 引入成熟依赖 `connectivity_plus`；
  - 在 `contracts/network/network_monitor.dart` 定义纯 Dart 接口并在应用层注入；测试环境使用纯内存 `MockNetworkMonitor`，确保 100% 离线高速运行。

## 4. 详细业务逻辑与执行规范

### 4.1 换源流程与匹配对齐 (Switch Source Workflow)
1. **触发与搜索**：
   - 用户在在线书详情或播放器点「换源」；
   - 系统调起 `SwitchSourceSheet`，并行调用所有已启用的 `book_sources` 执行 `search(book.title)`；
   - 过滤掉当前书源；若某一书源已有同名同作者入库且 `id != book.id`，标记为不可换并置灰提示；
2. **智能章节对齐算法**：
   - 候选卡片展示：书源名称、分组、最新章节名称、响应延迟；
   - 对当前选中的候选源，异步预拉取目录前 100 章与尾部章节，计算匹配度：
     - **精准标题匹配**：清洗标题文本（去除前缀「第xx章」、空格、标点）后一致，匹配置信度 100%；
     - **序号严格匹配**：若标题不一致但章节序号完全相等，匹配置信度 85%；
     - **无法匹配**：置信度 0%，卡片标橙「序号可能有差异」；
3. **换源提交事务**：
   - 开启数据库事务：
     - 将原书下所有非 retired 章节批量打上 `retired = true`；
     - 写入新书源关联（`books.library_root_id`、`books.root_path` 等）；
     - 同步更新旧 retired 章的 `library_root_id`；
     - 抓取并写入新源目录（采用 upsert 语义）；
     - 映射进度：若找到匹配的新章节，将播放进度更新至该新章节（位置百分比保留）；若未找到，保留旧进度并锁定防覆盖；
   - 提交事务后，后台异步调用 `AudioCacheRepository.clearBookCache(bookId)` 清理旧源的预下载临时文件，并通知播放器重建播放项。

### 4.2 目录刷新与防丢保护机制 (TOC Refresh & Safe Update)
1. **分页抓取保护**：
   - 遵循 Legado `ruleToc.nextTocUrl` 进行目录抓取；
   - 最多连续抓取 50 页；维护一个已访问 URL 集合，检测到循环引用立即终止；
   - 只有在**正常到达最后一页且全过程无 HTTP 异常**时，才打上 `complete = true`；
2. **增量比对与状态演进**：
   - 对比新抓取的章节列表与数据库中当前活动章节：
     - **新增章节**：插入数据库，`retired = false`；
     - **完全一致章节**：更新章节标题或 URL（若有微调）；
     - **消失的章节**：
       - 若抓取是 `complete == true`：标记为 `missing = true`，并置 `retired = true`；
       - 若抓取是 `complete == false`（中途网络超时或触顶 50 页）：**严禁修改消失章节的 missing/retired 状态**，保持原有旧章节，仅更新已抓到的新增章节；
   - 更新书籍状态：`books.last_refresh_at = now()`，若部分失败则写 `books.last_refresh_ok = false` 及脱敏错误原因，在书籍详情和书库行标「目录部分更新」，绝不报错退弹。

### 4.3 预下载编排与沙盒 LRU 缓存池 (Preload & Cache Architecture)
1. **预载触发条件**：
   - 仅在网络满足条件时启动（若开启「仅 Wi-Fi」且当前非 Wi-Fi，则挂起预下载）；
   - 仅针对普通直接音频格式（mp3, m4a, aac 等），HLS `.m3u8` 绕过；
   - 监听 `PlaybackController` 播放位置流：当 `currentPosition / totalDuration >= 0.5` 且尚未预载时，触发预下载后 `N` 章（默认 N=3）；
2. **下载与存储结构**：
   - 沙盒存储路径：`cache/audio_preload/<book_id>/<chapter_id>.audio`；
   - 写入元数据映射表或原子侧文件记录：`file_size`、`downloaded_at`、`last_accessed_at`；
3. **LRU 淘汰策略**：
   - 每次预下载完成或应用切后台时，检查总缓存占用量；
   - 若占用超过 `max_cache_bytes`（默认 2GB）：
     - 筛选出非当前正在播放、非当前预载窗口内的音频缓存文件；
     - 按照 `last_accessed_at` 升序排列（最早访问的优先）；
     - 依次删除物理文件，直至总占用降至 `max_cache_bytes * 0.85`（留出缓冲空间）。
4. **播放器对接无缝无感**：
   - `OnlineChapterSourceResolver` 解析音频时，优先检测本地是否存在完整且校验合规的预载文件；若存在直接以 `file://` 协议秒起播；若不存在则回退至网络流式并同时登记预载。

### 4.4 安全删除护栏规范 (Safe Delete Dialog)
1. **在线书籍删除**：
   - 选项 1：「移出书架」（默认推荐，`on_shelf = false`，保留播放历史、进度与在书库中的展示）；
   - 选项 2：「从书库彻底删除」（级联清理该书的章节、书签、历史记录及沙盒音频预下载缓存）。
2. **本机书籍删除**：
   - 弹窗展示书籍封面、标题及本地路径；
   - 选项 1：「从书库移除记录」（默认，不碰触任何用户磁盘文件，仅删除数据库索引）；
   - 选项 2：「同时删除磁盘上的本地音频目录」（复选框，默认**不勾选**，显式警告色；SAF 根或根目录强制置灰禁用）；
   - 若用户主动勾选选项 2，点确定后弹出醒目的二次警告确认对话框，防止任何误操作。

## 5. UI/UX 视觉与交互规范 (Look & Feel)

1. **换源抽屉 (`SwitchSourceSheet`)**：
   - 高度为屏幕高度的 60%~75%，圆角顶部 16dp；
   - 顶部提供当前书名、当前源与播放章节状态；
   - 搜索过程呈现微动效骨架屏（Shimmer），避免突兀跳动；
   - 候选源卡片具备鲜明的健康色微标（绿：响应快且匹配；橙：序号有偏差；红：响应失败）；
   - 底部提供「试听当前章」与「确认更换」主按钮。
2. **书库顶部呼吸胶囊 (`LibraryRefreshCapsule`)**：
   - 位于书库 AppBar 下方，高度 36dp，带微阴影与圆角 18dp；
   - 柔和显示当前刷新进度（例如「正在检查 3/8 本在线书更新...」）；
   - 点击可展开单行摘要，支持随时滑动忽略或关闭，不遮挡书目列表滚动与点击。
3. **播放器双层流式缓冲条 (`StreamCacheProgressBar`)**：
   - 底轨：低对比度背景色（深色模式下深灰，浅色模式下浅灰）；
   - 中轨：已缓存区间（带轻微半透明强调色）；
   - 上轨：当前播放游标。
4. **适配要求**：
   - 严格适配 320dp 紧凑窄屏，文字自适应换行，使用 `TextOverflow.ellipsis` 防止 RenderFlex 溢出；
   - 完整适配系统深色/浅色模式以及高对比度辅助功能；
   - 大字号（fontScale 2.0）下按钮与卡片内部自动纵向自适应，不写死固定高度。
